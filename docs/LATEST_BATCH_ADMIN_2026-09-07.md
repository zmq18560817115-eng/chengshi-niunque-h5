# 首页公开批次维护

本次按用户标记的区域新增后台维护：正装批次号、试用装批次号、检测日期。首页其他素材、位置、页面适配和动画时间保持原有设置。

## 操作

1. 登录 `/admin/login`，从导航进入“公开批次”（`/admin/site`）。
2. 修改三个字段。批次号接受 1–24 位英文字母、数字及 `. _ / -`，首位必须是字母或数字。
3. 检测日期接受 `YYYY-MM` 或 `YYYY-MM-DD`，例如 `2026-09` 显示为“2026年9月”，`2026-09-07` 显示为“2026年9月7日”。不存在的日期会阻止发布。
4. 点击“保存并发布”。重新打开首页会读取新内容；已打开的页面沿用现有 30 秒版本检查，在回到窗口时也会检查更新。

只输入了月份时不补造具体日期。尚未发布设置时，保持原图数据：正装 `GD00046087`、试用装 `GD00046086`、`2026年8月`。

## 数据与展示

- 使用已有 Prisma `SiteSetting`，键为 `latest-public-batch`，无需新增表或迁移。只公开已发布、上线且未删除的设置。
- 保存操作要求当前管理员登录；发布与 `LATEST_BATCH_PUBLISH` 操作记录在同一事务完成，记录修改前后值及操作者。
- 接收字段白名单只有三个批次字段，不能通过该表单修改首页标题或其他固定视觉内容。
- 默认三个值完全一致时继续使用原有图片，不叠加动态文字。750 × 1400 默认首屏与修改前截图逐像素一致。
- 自定义值使用原图派生的无数字批次层及 SVG 文字，保持 2000 像素母版坐标，随既有 750 设计稿 / vw 体系缩放。固定标签、人物与结果卡保持原样。
- 首页、引导页目的地预览、路由过渡缓冲及图片失败预览使用同一份数据。首次从原图数字切换为自定义数字时，先解码替代图片再一起更新，避免慢网下新旧数字重叠。
- 原稿与 `docs/input/` 未改动。两个派生图可用 `python scripts/refresh-design-assets.py --editable-batch` 重建（需脚本原有 Pillow / NumPy / OpenCV 环境）。完整素材生成也包含此步骤。

## 验证

- 必需检查：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm prisma:validate`、`pnpm build`。
- 单元及集成测试覆盖日期校验、字段白名单、登录边界、发布事务、操作记录、公开版本变化以及引导页/首页数据一致。
- `pnpm exec tsx --env-file-if-exists=.env scripts/verify-latest-batch.ts` 对本机 3100 端口执行浏览器验证：登录隔离、错误输入保留、保存后重新读取、已打开页面更新、慢加载切换、引导页进入和图片失败预览。包含 320 / 375 / 430 / 750 宽度检查。
- 浏览器验证临时发布测试批次，并在结束后恢复原设置、清理临时管理员、会话和测试日志。截图和验证输出位于忽略目录 `artifacts/latest-batch-qa/`，不包含会话令牌。
- 默认原图字形保持不变；新输入的文字采用系统字体，原稿对应文字的字体文件未提供，详见 `OPEN_QUESTIONS.md` 第 26 项。

本次结果：全部五项必需检查通过，41 个测试文件 / 271 项测试通过；浏览器 8 项流程检查通过，包含四档宽度和慢加载验证。默认截图逐像素差异为零，测试设置和账号已清理。
