# Design Mapping

## Homepage guide v1

The supplied 2000 x 4334 loading animation is a shared, adaptive runtime buffer rather than a fixed step before `/go` or any named route. Root `loading.tsx` waits 220ms before displaying it when Next is still preparing server data, and `AdaptiveReadinessGate` uses the same delayed visual only while the current guide, archive, or category page is still decoding its own critical artwork. The guide mounts its complete bootstrap canvas immediately and uses a longer 600ms threshold, so a normal cached entry never shows a loading screen in front of it. The archive gate uses a 160ms threshold and does not release on preload promises alone: it waits for the real first-screen archive `<img>` elements, font readiness, and three stable animation frames. Slow network or delayed browser paint therefore mounts the loading buffer automatically, while a genuinely ready cached homepage still hands off directly. There is no fixed playback duration; only the 260ms visual exit remains once the buffer was actually shown. Guide assets, optimized first-screen homepage component layers, and deferred page parts share one priority queue with a hard limit of four concurrent image requests. The guide is high priority; homepage first-screen assets warm at automatic priority and are promoted to high when `/reports` actually opens; lower-page artwork and motion then continue at low priority from both guide and direct-home entry. The discarded `no-store` JSON warm-up was removed because it could not be reused by the dynamic route and competed with the artwork. The immediately available loading poster is always the first buffer paint, while the 11.58MB animated layer is not requested unless the same buffer remains visible for 900ms; it stays low priority so it cannot delay current-page artwork. Failed images are still retried once with a 30000ms per-attempt ceiling before the page's existing visual fallback takes over. No API shape, persistence, or admin linkage changes.

引导页的 Logo、标题、说明和滑动提示均属于运行贴图，不从站点配置读取，也不在管理后台提供文字编辑字段；后台页面文案仅管理 `/reports` 档案首页与品牌初心区。

## Archive artwork and motion

`ReportsArchive` no longer renders `archive-reference.webp`. `ArchiveArtwork` assembles the approved artwork on one 1000 x 5557 master canvas and marks the composition with `data-artwork-source="layered-originals"`. Its first-screen paper and module-one component canvases have repository WebP derivatives under `public/design/final-v1/archive/runtime-layers/`, generated at their exact runtime dimensions; their layer geometry, transparency, and stacking coordinates are unchanged. This removes the 9.74MB paper PNG and avoids a second cold `/_next/image` request after an unrelated raw-PNG warm-up. Module-two folders remain separate supplied PNG parts and module three remains one supplied output part converted to its exact 1000 x 1183 runtime size. Only the first-screen components and unlock assets gate guide handoff; lower-page layers are true lazy images while the guide continues their low-priority background warm-up. Navigation hotspots and runtime motion stay above the static composition.

The module-one scroll-unlock ribbon uses the existing lossless `public/design/final-v1/archive-unlock-ribbon.webp` tight crop as its sole runtime image layer. The former 3034 x 4334 PNG contained visible alpha only in source bounds `(2479, 3634)-(2672, 4308)`; that exact 193 x 674 visible crop is pixel-equivalent when composited and reduces the decoded RGBA surface from about 50.16MiB to about 0.50MiB. ## Category cards and report content

The three category pages no longer mount a completed page screenshot. `CategoryDetail` reconstructs each 2000 x 4333 composition from the approved independent paper, wide folder/mascot, title ring, title digit, title text, shared footer note, and blank-card parts stored under `public/design/final-v1/category-runtime/`. The current approved runtime remains shifted 75px above the original export to preserve the earlier reduced top whitespace. Each 2502px folder layer keeps its measured asymmetric x offset and is allowed to extend beyond the central canvas while the fixed root clips the result, so short embedded-browser gutters receive the real painted folder edge rather than a flat sampled colour. `CategoryDetail` overlays `PublicReportCard.title`, `description`, and `buttonText` as normal HTML. Review and production status-fish parts remain delivered raster components, while the inspection fish remains part of its delivered blank card. This preserves the existing admin → Prisma → public-content service chain and keeps card clicks, report URLs, swipe-back, and motion live without altering server code.

The retired `category-*.webp`, `category-*-clean.webp`, inspection batch bubble, combined review-status fish, and duplicated Chinese-path status-fish folder were removed after their runtime references reached zero. The asset builder no longer regenerates those retired category canvases. The tertiary report page still renders the selected card title/description and each asset title/description as HTML, while report images or PDF previews remain replaceable assets. No schema, public URL, admin field, or storage behavior changed.

When a green, yellow, or brown archive module is opened from `/reports`, the pressed state is painted first. After 40ms the complete current archive viewport is cloned with that state already visible and navigation starts immediately; the frozen old viewport remains fully opaque and stationary while the destination route mounts and its primary 2000 x 4333 category artwork finishes loading. Only after that readiness signal do both pages move horizontally: the frozen homepage travels from `0` to `-100dvw`, while the ready category page travels from `100dvw` to `0`, both at opacity 1 with the same 1600ms `cubic-bezier(.35,0,.25,1)` timing. Their vertical edges meet throughout the leftward handoff; no canvas background, partial destination artwork, or double-exposed crossfade can appear. The persistent root buffer is removed 120ms after the slide finishes. A 12-second fail-open prevents a failed destination asset from trapping the route. Direct category URLs use the matching shorter right-to-left entrance. Category and report pages now expose a visible semantic “返回上一页” control in addition to the existing right-swipe gesture; both use the deterministic parent route. Reduced-motion mode replaces the paired slide with a 180ms continuity fade beginning at opacity 0.72.

Each category runtime root is fixed between the current safe-area insets and locks document scrolling while mounted. Its inner `category-page-viewport` keeps the source `2000 / 4333` aspect ratio and uses the smaller of the safe available width or dynamic height, centered in any remaining canvas area. The common paper component repeats behind the root at the same `-76px` design phase, while the independent 2502px folder layer extends through both gutters with `overflow: visible`; only the root performs clipping. No completed category screenshot, sampled theme colour, pseudo-element side strip, or stretched `cover` background participates in runtime rendering. This category-page gutter treatment is intentionally separate from the guide: the guide has no surround layer or pseudo side fill and instead uses one centered full-viewport cover transform for every registered 750 x 1625 layer. When an embedded mobile browser hides or restores its address bar, both the root and artwork recalculate together instead of leaving an exposed `body` strip; vertical overscroll is disabled and the page scroll position is reset to zero on entry. The full category source page is therefore visible on short 320 x 568 devices, 375 x 812 reference devices, and 430 x 932 large phones without cropping, stretching, or sitting under a system status bar. All backplates, hotspots, managed HTML copy, buttons, arrows, and status artwork remain inside the same inline-size container, so their shared 1000-unit coordinates and `cqw` typography scale together instead of drifting or deforming. Admin preview keeps the existing full-width proportional canvas rather than adopting the fixed runtime height or scroll lock.

The brand-story copy uses four fixed transparent line canvases. After trusted manual scrolling reaches the region at the 0.3 intersection threshold, the group waits 150ms. Each line reveals from left to right for 900ms; with a 500ms base step and offsets `[0, -100, 0, -200]`, the four line starts occur at 0ms, 400ms, 1000ms, and 1300ms after that delay. The final line therefore completes after 2350ms of cumulative visible playback. Time is deducted only while the assets are ready, the reveal has started, and the region remains visible; leaving the viewport pauses the completion timer and returning resumes the remaining duration. The artwork does not move or resize during the reveal.
