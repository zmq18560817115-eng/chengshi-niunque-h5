# Design Mapping

## Homepage guide v1

The supplied 2000 x 4334 loading animation is now a shared, adaptive runtime buffer rather than a mandatory 3600ms step before `/go`. Root `loading.tsx` displays it whenever a Next route is still preparing server data; `AdaptiveReadinessGate` uses the same visual while the current guide, archive, or category page is decoding its own critical artwork. There is no minimum playback duration: cached resources can hand off immediately, while slow resources keep the buffer present until their real `load` and `Image.decode()` work settles. Only the 260ms visual exit remains. `/go` waits for the guide artwork alone, while `/reports`, `/api/public/content`, and the complete homepage artwork/motion set warm in the background. The archive and each category perform their own readiness gate on direct or routed entry, so loading is no longer tied to a particular page order or transition. Existing route-continuity clones stay above this global buffer and release only when the destination gate has mounted ready content. Failed images are still retried once with a 30000ms per-attempt ceiling before the page's existing visual fallback takes over. No API shape, persistence, or admin linkage changes.

## Category cards and report content

The three category pages now use the design supplier's exact 2000 x 4333 reference artwork and eight blank card components from the 2026-08-25 delivery. Runtime copies live under `public/design/final-v1/category-runtime/`. Each full reference supplies the header character, folder silhouette, page texture, footer note, and exact stacking order. A matching blank card component is placed over every baked card region at its source half-scale coordinate; `CategoryDetail` then overlays `PublicReportCard.title`, `description`, and `buttonText` as normal HTML. Review and production status-fish parts are likewise the delivered raster components, while the inspection fish remains part of its delivered blank card. This preserves the existing admin → Prisma → public-content service chain and keeps card clicks, report URLs, swipe-back, and motion live without altering server code.

The retired `category-*.webp`, `category-*-clean.webp`, inspection batch bubble, combined review-status fish, and duplicated Chinese-path status-fish folder were removed after their runtime references reached zero. The asset builder no longer regenerates those retired category canvases. The tertiary report page still renders the selected card title/description and each asset title/description as HTML, while report images or PDF previews remain replaceable assets. No schema, public URL, admin field, or storage behavior changed.

When a green, yellow, or brown archive module is opened from `/reports`, the complete current archive viewport is cloned before the selected folder begins its existing 520ms extraction. Navigation begins after 220ms, but the frozen old viewport remains fully opaque and stationary while the destination route mounts and its primary 2000 x 4333 category artwork finishes loading. Only after that readiness signal do both pages move horizontally: the frozen homepage travels from `0` to `-100dvw`, while the ready category page travels from `100dvw` to `0`, both at opacity 1 with the same 1600ms `cubic-bezier(.35,0,.25,1)` timing. Their vertical edges meet throughout the leftward handoff; no canvas background, partial destination artwork, or double-exposed crossfade can appear. The persistent root buffer is removed 120ms after the slide finishes. A 12-second fail-open prevents a failed destination asset from trapping the route. Direct category URLs use the matching shorter right-to-left entrance, while swipe-back behavior, category-to-report navigation, and every non-category animation remain unchanged. Reduced-motion mode replaces the paired slide with a 180ms continuity fade beginning at opacity 0.72.

Each category runtime root is fixed to one stable small viewport height. Its inner `category-page-viewport` keeps the source `2000 / 4333` aspect ratio and uses the smaller of the available viewport width or height, centered in any remaining canvas area. The full source page is therefore visible on short 320 x 568 devices, 375 x 812 reference devices, and 430 x 932 large phones without cropping or stretching. All backplates, hotspots, managed HTML copy, buttons, arrows, and status artwork remain inside the same inline-size container, so their shared 1000-unit coordinates and `cqw` typography scale together instead of drifting or deforming. Admin preview keeps the existing full-width proportional canvas rather than adopting the fixed runtime height.

The brand-story copy uses four fixed transparent line canvases. After trusted manual scrolling reaches the region at the 0.3 intersection threshold, the group waits 150ms. Each line reveals from left to right for 900ms; with a 500ms base step and offsets `[0, -100, 0, -200]`, the four line starts occur at 0ms, 400ms, 1000ms, and 1300ms after that delay. The final line therefore completes after 2350ms of cumulative visible playback. Time is deducted only while the assets are ready, the reveal has started, and the region remains visible; leaving the viewport pauses the completion timer and returning resumes the remaining duration. The artwork does not move or resize during the reveal.
