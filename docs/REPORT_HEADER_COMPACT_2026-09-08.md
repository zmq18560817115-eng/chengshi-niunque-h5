# 第四层报告页顶部压缩

按用户截图标记，统一缩小全部第四层图片报告页的分类标签、标题、说明和报告工具区，让报告正文更早进入首屏。

- 使用 `src/app/globals.css` 中的报告字号 token。375px 屏宽下主标题由 33.75px 缩至 22.5px，说明文字为 13px，分类标签为 12px。
- 标题区上下留白改为 12px；报告名称、页码与缩放工具并排显示，工具区上下留白为 8px。
- 保留完整说明文字和报告标题；较长文本自动换行。缩放按钮仍有 44 × 44px 点击区域。
- 报告图片继续占满安全视口宽度。现有缩放、阅读位置保持、还原、翻页、手势与动画代码未修改。

## 验证

真实 `ImageReportViewer` 组件配合本地样例数据，在 320×568、375×812、430×932、750×1080、844×390 五档尺寸核验全部八类内容，共 40 组。全部无横向溢出、文字与按钮重叠，所有按钮点击区域不小于 44px。多页报告的放大、还原、上一页、下一页检查通过。

375px 的“核心营养含量”样例中，报告正文起点由 307.20px 提前至 159.19px，顶部区域高度减少约 48%。截图、前后尺寸及执行日志位于忽略目录 `artifacts/report-header-qa/`。

`pnpm lint`、`pnpm typecheck`、`pnpm prisma:validate`、`pnpm build` 通过。`pnpm test` 共 302 项通过、11 项失败、6 项跳过；失败项依赖未启动的本地 PostgreSQL（`localhost:5432`），Docker 引擎也未运行，因此本轮未完成真实数据库与对象存储联调。浏览器检查使用样例数据，不代表线上数据验收。
