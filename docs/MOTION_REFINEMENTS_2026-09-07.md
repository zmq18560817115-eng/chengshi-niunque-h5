# 引导标识与首页部件微调

- 引导页下方标识保留原先 900ms 的渐显上移入场，随后每 1800ms 上下跳动一次，位移由自身高度的 14% 增至 30%。横竖屏共用规则；减少动态效果模式保留静态展示。
- 紫色下滑条由引导过渡层紧接第二组批次卡片播放，800ms 入场曲线、最终位置及自然滚动保持不变。首页标识在过渡层下方按相同的 CSS 动画时钟准备和播放，保留未来开始时间对应的延迟；交接前对齐实际动画起点，避免渲染繁忙时 JS 时间与 CSS 首帧偏差造成位置跳动。收尾计时器等待实际动画结束，不截断剩余帧。
- 两张纸片从约半露出的状态继续上移和渐显。两张原始图片已有不同程度被文件夹遮挡，因此分别使用自身高度 22% 和 18% 的起始下移量、0.5 的起始透明度；原有 672ms 时长、滚动触发、层叠顺序、最终位置和返回时保持终态的行为不变。

未修改后台、文案、报告数据、源素材文件或其他交互。

验证：lint、typecheck、306 项测试、Prisma 校验和生产构建。浏览器脚本分别检查标识进入及循环跳动、第二组和紫色条的时间衔接、纸片起始位移与最终坐标，并覆盖 Chromium / WebKit、长短竖屏、横屏及减少动态效果模式。证据在忽略目录 `artifacts/guide-hint-entry-qa/`、`artifacts/ribbon-entry-qa/` 和 `artifacts/folder-paper-qa/`。

本次标识微调追加验证：五项项目检查通过，自动化测试共 319 项。跳动幅度检查覆盖 Chromium / WebKit、四种横竖屏尺寸和减少动态效果模式（10 个场景）。新增逐帧衔接脚本 `scripts/verify-ribbon-continuity.mjs`：修复前首页标识在过渡层淡出期间仍隐藏，估算可见透明度从峰值回落约 0.60；修复后六个场景（双浏览器、375/430px，以及 Chromium 四倍 CPU 降速）均无该回落，两层动画位置差小于 2px。证据在忽略目录 `artifacts/ribbon-continuity-qa/`。本次运行时代码仅调整引导标识幅度和紫色标识衔接，纸片及其他部件保持原样。
