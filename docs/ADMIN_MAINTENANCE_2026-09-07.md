# 批次与报告图片管理

登录 `/admin/login` 后，只需在 `/admin` 一个页面完成维护。

## 可修改内容

- 首页：正装批次号、试用装批次号、检测日期，点击“保存并发布”更新。
- 报告页：展开对应项目，上传一组有序图片作为一份报告；保存前可预览、上移、下移或移除待上传图片。已有报告可“替换并发布”全部图片，也可移除整份报告。
- 支持 JPG、PNG、WebP 静态图片；单张不超过 10MB，一份最多 30 张、合计 100MB。Next Server Actions 与 Nginx 请求上限统一为 105MB，预留表单开销。

分类、卡片标题和说明、页脚、顺序、上下线状态、固定素材及前端交互均不提供编辑。旧分类、卡片、站点设置、预览和记录页面跳回统一管理页；旧写入动作和分类创建 API 已关闭。数据库原有记录与操作审计保留，无需迁移。

## 对应关系与一致性

管理端按现有 3 个分类 / 8 个固定卡片 ID 对应前端报告页，显示标题使用与前端相同的文案解析。每个项目提供直达其前端页面的链接。

图片保存由专用服务处理，只接收报告项目、报告 ID、版本和图片文件；不接受客户端的标题、状态、存储路径等编辑。先核验项目与报告归属，再验证全部文件、上传到存储，最后在事务中更新报告图片页与审计记录。写入前重新检查项目版本并锁定卡片，旧表单不会覆盖已更新的报告；失败上传会清理本次新文件。替换不会删除其他报告，也不会变更卡片与分类字段。

旧图片对象保留以供审计恢复；被替换的图片页 ID 不再公开可读，整份报告移除后也会立即停止公开读取。管理端缩略图必须登录，通过存储抽象读取，并禁止缓存。

发布后管理端刷新，公开内容版本随图片变化更新；前端继续沿用现有版本轮询与重新聚焦检查。保存图片不会改动首页批次，保存批次也不会改动报告图片。

## 验证

新增测试覆盖项目归属、旧入口拒绝写入、私有图片读取、图片排序、上传失败保留选择、发布/替换/移除后的公开数据版本，以及所有卡片、分类和批次字段不被改动。集成验证使用自动回滚的真实数据库事务和内存图片存储，测试报告不会出现在当前公开页面。

浏览器验收为 `tests/e2e/admin-styles.spec.ts`，检查登录、统一入口、8 个对应项目、选图预览与排序、手机布局和旧页面跳转，不提交测试图片。

本轮通过 `pnpm lint`、`pnpm typecheck`、`pnpm test`（46 个测试文件、304 项测试）、`pnpm prisma:validate` 和生产构建；浏览器验收通过，桌面与手机截图位于忽略目录 `artifacts/admin-maintenance-qa/`。最后分类名称映射调整另经集成测试验证。前端 H5 组件及展示配置没有改动。
